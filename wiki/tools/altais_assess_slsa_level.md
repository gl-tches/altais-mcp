# `altais_assess_slsa_level`

Assesses the achieved SLSA v1.2 Build Track level (0–3) from a set of build-process facts.

| Property | Value |
|----------|-------|
| Module | [`sdlc`](../modules/sdlc.md) |
| Tool type | Auditor (emits findings) |
| Annotations | `readOnlyHint: true` · `destructiveHint: false` · `idempotentHint: true` · `openWorldHint: false` |

## Description

Assesses the achieved SLSA v1.2 Build Track level (0–3) from a set of build-process facts: scripted build, hosted build service, provenance generation / authentication / service-generation, and an isolated, hermetic, parameterless build. It emits a finding stating the current level and lists the exact requirements needed to reach the next level. An agent calls this when evaluating supply-chain build maturity.

## Input parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `config` | `object` | Yes | Declared build-process facts. |
| `config.scripted_build` | `boolean` | No | Whether the build is fully scripted (no manual steps). |
| `config.build_service` | `boolean` | No | Whether the build runs on a hosted build service. |
| `config.provenance_generated` | `boolean` | No | Whether build provenance is generated. |
| `config.provenance_authenticated` | `boolean` | No | Whether the provenance is authenticated. |
| `config.provenance_service_generated` | `boolean` | No | Whether the provenance is generated by the build service itself. |
| `config.isolated_build` | `boolean` | No | Whether the build runs in an isolated environment. |
| `config.hermetic` | `boolean` | No | Whether the build is hermetic (no undeclared inputs). |
| `config.parameterless` | `boolean` | No | Whether the build is parameterless. |
| `filename` | `string` (1–512 chars) | No | Filename used for the finding location. |

## Output

Returns `{ summary: { total, by_severity }, findings: [...] }`. The primary finding (rule `slsa-level`) states the current Build Track level in its title and lists the requirements to reach the next level in its description. Each finding has the standard shape `{ id, module, rule, severity, cwe, title, description, location?, evidence?, remediation, references, tags, status }`. Findings are appended to the session report.

## Example

**Request**

```json
{ "config": { "scripted_build": true, "build_service": true, "provenance_generated": true } }
```

**Response (excerpt)**

```json
{
  "summary": { "total": 1, "by_severity": { "medium": 1 } },
  "findings": [
    {
      "rule": "slsa-level",
      "cwe": ["CWE-1357"],
      "title": "Build Track Level 1",
      "description": "Requirements to reach Level 2: ...",
      "status": "open"
    }
  ]
}
```

## Detections

- `slsa-level` — reports the current SLSA v1.2 Build Track level (0–3) and the requirements to reach the next level (CWE-1357)
